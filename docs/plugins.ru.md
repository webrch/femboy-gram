# Плагины Femboy

[English](plugins.md) · **Русский** · [中文](plugins.zh.md)

Плагин — это код на питоне, который выполняется внутри форка. Не отдельная
программа, не бот со стороны: он живёт в том же приложении, что и переписка.

## Правило форума

**Код плагина не обфусцируется.** Он едет исходником, и открыть его должен
мочь любой. Обфускация — бан на форуме.

Причина простая: песочницы здесь нет. Проверить, что плагин делает, можно
только одним способом — прочитать его. Спрятанный код лишает этой
возможности всех сразу.

## Честно про безопасность

Плагин может всё, что может само приложение: читать переписку, писать от
вашего имени, лезть в файлы. Разрешения в манифесте — **заявление автора**, а
не ограничение; приложение их не проверяет и проверить не может.

Ставьте только то, что прочитали сами или чему доверяете.

## Формат .marp

Обычный zip, переименованный в `.marp`:

```
femboy_example.marp
├── manifest.json   обязательно
├── main.py         обязательно
├── icon.png        по желанию
└── ...             всё остальное, что нужно плагину
```

`icon.png` показывается в списке плагинов. Картинка квадратная, 128×128 хватит.

## manifest.json

```json
{
  "id": "femboy.example",
  "name": "Пример",
  "version": "1.0",
  "author": "femboygram",
  "description": "Здоровается в консоли.",
  "min_version": "0.3",
  "permissions": ["ui"]
}
```

| Поле | Что это |
|---|---|
| `id` | Номер плагина. Латиницей, с точками. По нему плагин обновляется и хранит настройки — менять нельзя. |
| `name` | Имя в списке. |
| `version` | Версия, строкой. |
| `author` | Кто написал. |
| `description` | Одна-две строки: что делает. |
| `min_version` | Самая старая версия Femboy, на которой плагин работает. На версии старее он не поставится вовсе — с объяснением, а не молча. Поле необязательное. |
| `permissions` | Что плагин о себе заявляет. Список ниже. |
| `name_en`, `name_zh`, `description_en`, … | То же на другом языке. Приложение возьмёт по своему языку, а нет перевода — возьмёт обычное поле. |

Разрешения: `read_chats`, `send_messages`, `edit_messages`,
`delete_messages`, `change_profile`, `ui`. Своё имя тоже можно — оно покажется
как есть.

## main.py

```python
def on_start():
    femboy.log("привет из плагина", femboy.name)
```

`on_start()` вызывается при запуске плагина. Если его нет, плагин просто
выполняется сверху вниз.

Объект `femboy` доступен без импорта:

| | |
|---|---|
| `femboy.id` | номер из манифеста |
| `femboy.name` | имя из манифеста |
| `femboy.folder` | папка плагина на телефоне |
| `femboy.log(*части)` | строка в консоль |
| `femboy.error(*части)` | то же, но красным |
| `femboy.ui(вызов, delay_ms=0)` | выполнить на главном потоке — всё, что трогает экран, только оттуда |
| `femboy.every(мс, вызов)` | повторять каждые `мс`. Возвращает ручку |
| `femboy.cancel(ручка)` | прекратить повтор |
| `femboy.toast(текст)` | короткая надпись поверх экрана |
| `femboy.get(ключ, запасное=None)` | своя память плагина |
| `femboy.set(ключ, значение)` | записать в неё |
| `femboy.flag(ключ, запасное=False)` | прочитать переключатель с экрана настроек как да/нет |
| `femboy.background(вызов)` | сделать что-то долгое в стороне от экрана |
| `femboy.send(чат, текст)` | отправить сообщение в переписку |
| `femboy.fetch(адрес, вызов)` | сходить в сеть и позвать `вызов(текст)`; не получилось — `None` |
| `femboy.activity()` | текущий экран приложения |
| `femboy.window(заголовок, вид)` | показать своё окно в оформлении приложения |
| `femboy.color(0xFFRRGGBB)` | цвет в том виде, в каком его понимает андроид |

`get` и `set` переживают и перезапуск, и обновление самого плагина: они лежат
не в папке плагина, а её при обновлении заменяют.

## События

Плагин не опрашивает приложение — приложение зовёт плагин.

| | |
|---|---|
| `femboy.on_chat_opened(вызов)` | открыли переписку; передадут сам экран |
| `femboy.on_send(вызов)` | человек отправляет текст, до отправки |
| `femboy.on_send_photo(вызов)` | человек отправляет картинку; можно заменить текстом |
| `femboy.on_message(вызов)` | пришло сообщение |
| `femboy.on_deleted(вызов)` | сообщения удалили |
| `femboy.on_pin(вызов)` | чат закрепляют или открепляют; можно отменить |
| `femboy.button(название, вызов)` | своя строчка в меню чата (три точки) |
| `femboy.on_settings(вызов)` | человек поменял настройку плагина |
| `femboy.pick_file(вызов, types=)` | спросить у человека файл |

Дверей нарочно немного, и каждая названа. Названная дверь переживает
обновление телеграма, потому что за неё отвечаем мы, а не совпадение имён:
поменяется внутренность — поправим мы, а плагин не заметит.

Подменить можно и любой другой метод приложения — про это [ниже](#подмена-любого-метода),
— но это другое обещание. Точнее, это отсутствие обещания: подмена держится
на имени чужого метода, а имя нам никто не гарантировал.

Если нужна дверь, которой нет, — [на форум](https://t.me/femboygram).
Добавим названную, а не станем открывать все сразу.

### Открыли чат

```python
def on_start():
    femboy.on_chat_opened(сесть_на_поле)

def сесть_на_поле(чат):
    поле = чат.getChatActivityEnterView()
    ...
```

Зовут каждый раз, когда открывается экран переписки, и отдают этот экран.

### Отправка

```python
def on_start():
    femboy.on_send(подписать)

def подписать(текст, чат):
    if текст.startswith("/"):
        return False          # не отправлять вовсе
    return текст + " 🌿"      # уйдёт вот это
```

Что вернуть: строку — она и уйдёт вместо набранного; `False` — не отправлять;
ничего — оставить как есть. Если подписаны несколько плагинов, их зовут по
очереди, и каждый видит текст после предыдущего.

Это единственное событие, которого приложение **ждёт**: пока обработчик
думает, человек смотрит на неотправленное сообщение. Если обработчик думал
дольше десятой доли секунды, в консоли об этом напишут — не в укор, а чтобы
автор знал.

> **Из обработчика отправки нельзя ходить в сеть.**
>
> Это не совет, а предупреждение. Обработчик исполняется на том же потоке,
> который рисует экран: пока идёт запрос, телефон не рисует ничего. Запрос с
> таймаутом в шесть секунд — это шесть секунд замершего приложения, а три
> запроса подряд — восемнадцать.
>
> Обычно андроид ловит такое сам и роняет приложение с понятным объяснением.
> Здесь эта защита не сработает: она живёт в джавовых сокетах, а питон ходит
> в сеть своими, мимо джавы. Ни падения, ни предупреждения — просто замершее
> приложение. Первые два плагина не от нас написаны именно так, и оба автора
> были уверены, что у них всё хорошо.
>
> Как надо — ниже, в «Команде с ответом из сети».

### Картинка вместо фото

```python
def on_start():
    femboy.on_send_photo(вместо_фото)

def вместо_фото(путь, подпись, чат):
    if подпись.strip() != ".ascii":
        return None           # не наша подпись — фото уйдёт как обычно
    return "```\n" + нарисовать(путь) + "\n```"
```

`путь` — файл на диске, `подпись` — то, что набрали под фото.

Что вернуть: строку — фото не уйдёт, вместо него уйдёт этот текст; `False` —
не уйдёт ничего; ничего — фото уходит обычным путём. Первый, кто взялся, тот
картинку и забирает: делить её между двумя плагинами не на что, поэтому
цепочки, как у текста, здесь нет.

Текст можно обернуть в тройные кавычки — тогда он уйдёт моноширинным блоком.
Для рисунков из знаков это не украшение, а условие: в обычном шрифте буквы
разной ширины, и любая картинка из них разъезжается.

В отличие от `on_send`, зовут **не из главного потока**. Значит, разобрать
картинку прямо здесь можно и нужно: экран в это время живой. В сеть отсюда
по-прежнему лучше не ходить, но уже по обычной причине — человек ждёт
отправки, — а не потому, что телефон замрёт.

Отказываться надо молча и часто. Не ваша подпись, не открылся файл, не
хватило места — верните `None`, и фото уйдёт само. Съесть чужую отправку и
промолчать хуже, чем не сработать.

Готовый плагин на этой двери лежит рядом: [femboy.ascii.marp](femboy.ascii.marp),
исходником внутри.

### Команда с ответом из сети

```python
def on_start():
    femboy.on_send(команда)

def команда(текст, чат):
    if текст.strip() != ".погода":
        return None
    femboy.background(lambda: femboy.send(чат, погода()))
    return False        # саму команду в чат не отправляем

def погода():
    ...                 # тут можно и в сеть, и надолго
```

| | |
|---|---|
| `femboy.background(вызов)` | сделать долгое в стороне от экрана |
| `femboy.send(чат, текст)` | отправить сообщение в переписку |
| `femboy.dont_send()` | то же, что вернуть `False` |

Отменить отправку можно тремя способами, и все три равны: вернуть `False`,
позвать `femboy.dont_send()` или `femboy.cancel()` без аргумента. Три
потому, что за отменой тянутся рукой именно к `cancel`, а он до этого значил
только «останови повтор» — и молча ничего не отменял.

### Приход сообщений

```python
def on_start():
    femboy.on_message(считать)

def считать(текст, чат, номер, своё):
    if not своё:
        femboy.log("пришло:", текст)
```

Приходят и свои отправленные — на то и `своё`, чтобы их отличить. Ответ ни на
что не влияет: сообщение уже пришло.

### Своя кнопка в чате

```python
def on_start():
    femboy.button("Посчитать", посчитать)

def посчитать(чат):
    femboy.toast("тут " + str(чат.getMessagesCount()) + " сообщений")
```

Строчка встаёт в меню чата, последней, после всех обычных пунктов: чужой код
не должен раздвигать привычное меню.

Если у одного плагина вызов упадёт, остальных это не отменит: каждого зовут
отдельно, а упавший получает свой разбор в консоли.

`print()` тоже уходит в консоль — перехвачен.

### Удаление сообщений

```python
def on_start():
    femboy.on_deleted(запомнить)

def запомнить(номера, чат):
    femboy.log("удалили", len(номера), "в", чат)
```

Номера — список, `чат` — номер канала или ноль для обычной переписки. Ответ ни
на что не влияет: сообщений уже нет.

Само сообщение к этому времени пропало — прочитать его отсюда нельзя. Кому
нужен текст удалённого, тот должен был запомнить его раньше, в `on_message`.
Двери «покажи, что удалили» не существует и не появится: приложение узнаёт об
удалении в тот же миг, что и вы.

### Закрепление

```python
def on_start():
    femboy.on_pin(не_закреплять_чужое)

def не_закреплять_чужое(чат, закрепляют):
    if закрепляют and чат < 0:
        femboy.toast("каналы не закрепляем")
        return False
```

Вернуть `False` — не закреплять. Это первая дверь не в переписку, а в сам
список чатов.

Приложение ждёт ответа, как и на отправке: пока обработчик думает, человек
смотрит на нажатую кнопку. Долгую работу отсюда уносить в
`femboy.background`.

### Файл от человека

```python
def on_start():
    femboy.button("Выбрать картинку", выбрать)

def выбрать(чат):
    femboy.pick_file(готово, types="image/*")

def готово(путь):
    if путь is None:
        femboy.toast("передумали")
        return
    femboy.log("выбрали:", путь)
```

`types` — что показывать в проводнике: `"image/*"`, `"text/plain"`. Пусто —
любые файлы.

Обработчик зовут в любом случае, и при отказе тоже — тогда путь придёт `None`.
Молчать было бы хуже: плагин остался бы ждать ответа, которого не будет.

Выбранное копируется в папку этого плагина, и путь — на копию. Проводник
отдаёт не путь, а адрес с временным правом на чтение: оно живёт до
перезапуска и из питона не открывается. Копия — то, чем плагин сможет
пользоваться дальше.

Собирать `Intent` руками не надо и не выйдет: мост питона выбирает конструктор
отражением и добирается до скрытого `Intent(Parcel)`, которого на деле нет.
Эта дверь и сделана затем, чтобы туда не лезть.

## Подмена любого метода

Всё, что выше, — двери, которые мы открыли нарочно. Иногда нужного нет, а
ждать нельзя. Тогда — `femboy.hook`: подменить любой метод приложения, как
это делают модули Xposed.

Сначала выключатель: с FemboyGram 2.0 хуки идут вместе с плагинами, под одним выключателем в **Настройки → FemboyGram → Плагины** (после него приложение перезапускается). По
умолчанию выключено, и это не перестраховка. Кривой хук роняет приложение прямо
при запуске — а выключить его тогда негде, потому что настройки лежат внутри
того самого приложения, которое не открывается.

Защита есть: если запуск с хуками не дожил до конца, следующий поднимется без
них и скажет об этом. Но защита — это сетка, а не обещание, и натянута она под
вами, а не под вашим плагином.

```python
def on_start():
    if not femboy.hooks_work():
        femboy.log("хуков нет:", femboy.hooks_why())
        return

    femboy.hook(
        "org.telegram.messenger.MessagesController",
        "isDialogMuted",
        args=["long", "long"],
        after=показать,
    )

def показать(вызов):
    femboy.log("тихий?", вызов.getResult())
```

| | |
|---|---|
| `femboy.hooks_work()` | поднялись ли хуки вообще |
| `femboy.hooks_why()` | почему не поднялись, если не поднялись |
| `femboy.hook(класс, метод, before=, after=, args=)` | подменить |

`args` нужен, только если метод перегружен, и пишется типами: `"int"`,
`"long"`, `"java.lang.String"`. У обработчика один довод — `вызов`:

| | |
|---|---|
| `вызов.args` | доводы вызова, их можно менять в `before` |
| `вызов.thisObject` | у какого объекта позвали; у статических — `None` |
| `вызов.getResult()` | ответ метода (в `after`) |
| `вызов.setResult(x)` | подменить ответ; в `before` это ещё и отмена вызова |

`femboy.hook` возвращает `False`, если подменить не вышло, и пишет причину в
консоль. Молча делать вид, что подменили, он не станет: плагин, который думает,
что работает, хуже плагина, который честно не работает.

**Чего ждать.** Имена методов телеграма нам никто не обещал: сегодня метод
называется так, завтра иначе, и хук просто перестанет находиться. Поэтому
`hooks_work()` спрашивают до, а не после, и плагин должен уметь обойтись без
хука, а не разваливаться. Рут для этого не нужен: подмена живёт внутри одного
приложения и только пока оно запущено. Другие приложения ей недоступны.

Если хук нужен постоянно и многим — [напишите на форум](https://t.me/femboygram).
Из хука, который прижился, получается названная дверь, а названная дверь
переживает обновление.

## Свой экран настроек

Плагин не рисует свои экраны — он говорит, из чего экран состоит, а рисует
приложение. Поэтому переключатель у плагина такой же, как везде: та же тема,
тот же цвет, то же нажатие.

```python
def on_start():
    femboy.settings(
        femboy.header("Как здороваться"),
        femboy.switch("hello", "Здороваться", default=True,
                        about="Пишет привет, когда открываешь чат."),
        femboy.text("name", "Имя", default="друг"),
        femboy.choice("mood", "Настроение", ["весело", "спокойно"]),
        femboy.note("Всё это хранится на телефоне и никуда не уходит."),
        femboy.action("Забыть всё", забыть, danger=True),
    )
    femboy.on_settings(поменяли)

def поменяли(ключ, значение):
    femboy.log("теперь", ключ, "=", значение)

def забыть():
    femboy.toast("забыл")
```

| Строка | Что это |
|---|---|
| `femboy.header(текст)` | заголовок раздела |
| `femboy.note(текст)` | пояснение серым |
| `femboy.switch(ключ, название, default=False, about=None)` | переключатель; читается через `femboy.flag(ключ)` |
| `femboy.text(ключ, название, default="", about=None)` | строка, которую вписывают руками; читается через `femboy.get(ключ)` |
| `femboy.choice(ключ, название, варианты, default=None)` | выбор одного из нескольких |
| `femboy.action(название, вызов, danger=False)` | кнопка, которая просто что-то делает |

`settings()` зовут один раз, при запуске. Значения по умолчанию проставляются
сразу же — иначе первое чтение вернуло бы пустоту, хотя человек ничего не
менял.

У плагина с настройками в списке появляется шестерёнка. Нажатие по строке
слева от неё открывает настройки, нажатие по переключателю справа — включает
и выключает сам плагин.

Заявка хранится вместе с памятью плагина, а не в оперативной, поэтому экран
настроек открывается и у выключенного плагина: поправить настройку может
понадобиться до того, как включать.

## Три ловушки на стыке с андроидом

Всё это найдено не в теории, а при написании плагина с играми, и каждая
стоила отдельного захода.

**Цвет — знаковое число.** В java цвет это 32-битное число со знаком, и всё,
что непрозрачно, в нём отрицательное. Питон считает `0xFFFFFFFF` просто
большим числом, и мост в java отказывается его превращать:

```
OverflowError: value too large to convert to int32_t
```

Поэтому цвет надо пересчитывать:

```python
def argb(value):
    return value - 0x100000000 if value > 0x7FFFFFFF else value

view.setTextColor(argb(0xFFFFFFFF))
```

Падает это на первом же цвете, то есть экран не появляется вообще, и по виду
не отличить от «плагин не запустился».

**Список питона — не массив java.** Если метод ждёт массив, список ему не
подойдёт:

```python
from java import jarray
from java.lang import CharSequence

titles = jarray(CharSequence)(["Первое", "Второе"])
```

**Экран трогать только с главного потока.** Событие `on_send` уже на нём, а
вот кнопка на экране настроек — нет. Оттуда любое окно надо открывать через
`femboy.ui`, иначе не откроется ничего.

Ошибки такого рода видны только в консоли: Настройки → FemboyGram → Плагины →
Консоль. Там будет и строка, и причина.

## Что доступно кроме этого

Питон здесь настоящий, с доступом к java-классам приложения:

```python
from java import jclass

Config = jclass("org.telegram.femboy.FemboyConfig")
femboy.log("ватермарка:", Config.watermarkOnSend())
```

Отсюда достаётся всё остальное приложение. Это и есть «плагин может всё» —
не оборот речи.

## Консоль

Настройки → FemboyGram → Плагины → Консоль. Туда уходит вся печать плагинов и
их ошибки, ошибки красным. Питон падает молча, так что без консоли о своей
опечатке автор узнаёт только по тому, что «ничего не работает».

## Установка

Настройки → FemboyGram → Плагины → Установить из файла. На окне установки видно
автора и заявленные разрешения.

Ещё можно нажать на файл `.marp` прямо в чате — приложение предложит его
поставить.

На окне установки есть две кнопки. «Поставить» ставит плагин выключенным.
«Поставить и включить» ставит, включает и сразу перезапускает Femboy —
плагин начинает работать, не дожидаясь, пока приложение закроют вручную.

Если плагин заявил `min_version` выше вашей, он не поставится, и вам скажут,
какая версия нужна, — вместо того чтобы поставиться и сломаться.

На окне установки есть кнопка «Посмотреть архив»: она открывает `.marp` тем,
что на телефоне умеет архивы, — прочитать код можно до установки, а не после.
Правило форума требует, чтобы код был открыт; значит, и открыть его должно
быть чем.

Долгое нажатие на строку — карточка плагина и удаление.

Выключение значит «больше не запускать». Уже работающий питоновский код
остановить нечем — он доживёт до перезапуска приложения. Поэтому на экране
плагинов есть кнопка «Перезапустить FemboyGram»: выключили — нажали — плагина
больше нет.

### Плагины exteraGram

Файл `.plugin` от exteraGram ставится так же: нажать на него в чате или
выбрать в «Установить из файла». Femboy переводит его в `.marp` и перед
установкой говорит, чего из нужного плагину у нас нет.

Модули их SDK лежат в приложении под теми же именами: `base_plugin`,
`client_utils`, `android_utils`, `hook_utils`, `file_utils`, `plugin_settings`,
`markdown_utils`, `ui.settings`, `ui.alert`, `ui.bulletin`,
`extera_utils.classes`, `extera_utils.text_formatting`. Работают:

- хуки методов `hook_method`, `hook_all_methods`, `hook_all_constructors`
  через их же `MethodHook` и `MethodReplacement`, с фильтрами `HookFilter`
  (условия считает MVEL, как у них);
- хуки отправки, запросов и обновлений с их сигнатурами;
- отправка текста, фото, видео и файлов, правка сообщений;
- наследование java-классов из питона, `java_subclass` (dexmaker, как у них);
- плагины-библиотеки вроде zwylib: другой плагин делает `import zwylib`, и
  если библиотека стоит, она поднимается сама;
- `packaging` и `typing_extensions` уже в приложении.

Чего нет: меню скрепки, хуков интентов и файлов, своих строк `Custom` в
настройках, подэкранов настроек (их строки показываются на том же экране) и
установки пакетов пипом на ходу.

### Магазин

Вторая вкладка на том же экране — плагины из канала
[@femboyg_plugins](https://t.me/femboyg_plugins). Ставятся в одно нажатие, тем же
окном установки и с теми же вопросами: канал не делает чужой код проверенным.
Никто эти плагины не смотрел — мы тоже. Читайте код.

Чтобы плагин попал в магазин, выложите `.marp` файлом в канал. Имя файла станет
именем в списке, подпись под файлом — описанием. Порядок в магазине по времени:
новое сверху.

### Что включается вместе с плагином

Галочка «включить после установки» означает «пусть работает». Если сама система
плагинов выключена, она включится: иначе просьба невыполнима, а раньше плагин
молча ничего не делал, и догадаться было нечем.

Если плагин пользуется хуками, окно установки скажет об этом отдельной строкой,
а включение плагина включит и хуки. Про хуки спрашивают не из вежливости —
[выше](#подмена-любого-метода) написано, чем они опасны.
